Судя по описанию, первый запуск прошёл нормально: диск раскрутился, работает равномерно, не пытается повторно запускаться и определяется Raspberry Pi как `/dev/sda`.

А структура разделов, которую ты увидел, очень похожа на стандартную разметку диска с ZFS:

- `/dev/sda` — физический HDD на 22 ТБ.
- `/dev/sda1` — основной раздел, содержащий данные ZFS.
- `/dev/sda9` — небольшой служебный раздел, который ZFS обычно создаёт при использовании GPT.

Наличие `sda9` — совершенно нормальное явление для ZFS. Оно само по себе не указывает на повреждение разметки или диска.

Но пока не следует считать файловую систему подтверждённой только по структуре разделов.

## Как правильно обращаться с ZFS

ZFS отличается от ext4 и NTFS. Обычно мы не монтируем `/dev/sda1` напрямую командой `mount`. Вместо этого ZFS обнаруживает и импортирует пул (pool), а внутри него могут находиться несколько отдельных файловых систем — datasets.

Для твоей ситуации предлагаю такой порядок:

1. Обнаружить ZFS-пул, не изменяя содержимое диска.
2. Импортировать его в режиме только для чтения.
3. Посмотреть файлы, структуру datasets и состояние пула.
4. Если всё хорошо, при необходимости перейти к обычному режиму чтения и записи.
5. Перед отключением диска выполнить `zpool export` — это штатный способ безопасно завершить использование пула.

Именно `zpool export`, а не просто `umount`, будет основной командой при завершении работы.

## 1. Убедимся, что Raspberry Pi поддерживает ZFS

Сначала проверь, установлен ли ZFS:

```
command -v zpool
command -v zfs
```

Если команды существуют, выполни:

```
sudo zpool version
sudo zpool list
```

Если `zpool` не установлен или сообщает о недоступности модуля ядра, пока не устанавливай пакеты вслепую.

В Raspberry Pi OS поддержка ZFS зависит от версии системы, ядра и доступных модулей. Для установки часто используются `zfsutils-linux` и `zfs-dkms`, но последний должен быть совместим с текущим ядром Raspberry Pi.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://forums.raspberrypi.com\&sz=32)

Raspberry Pi Forums



В таком случае сначала пришли вывод:

```
cat /etc/os-release
uname -r
apt-cache policy zfsutils-linux zfs-dkms
```

## 2. Обнаружение ZFS-пула

Если ZFS работает, выполни:

```
sudo zpool import
```

Эта команда без дополнительных аргументов ничего не импортирует и не записывает на HDD. Она просто ищет доступные для импорта пулы.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://openzfs.github.io\&sz=32)

OpenZFS documentation



Пример возможного результата:

```
   pool: backup
     id: 1234567890
  state: ONLINE
 action: The pool can be imported using its name or numeric identifier.
 config:

        backup      ONLINE
          sda1      ONLINE
```

Здесь `backup` — вымышленное имя, а не название твоего пула.

Если обнаружится несколько устройств или ZFS сообщит, что часть устройств отсутствует, не импортируй пул до выяснения его конфигурации.

## 3. Первое подключение — только для чтения

Предположим, что имя найденного пула — `backup`.

Создай временную директорию:

```
sudo mkdir -p /mnt/zfs-inspect
```

Теперь импортируй пул:

```
sudo zpool import \
  -N \
  -o readonly=on \
  -R /mnt/zfs-inspect \
  backup
```

Это мой рекомендуемый способ первого подключения.

Каждый параметр здесь важен:

| Параметр              | Назначение                                                                                |
| --------------------- | ----------------------------------------------------------------------------------------- |
| `-N`                  | Не монтировать файловые системы автоматически                                             |
| `-o readonly=on`      | Импортировать пул без записи на диск                                                      |
| `-R /mnt/zfs-inspect` | Использовать временный корень для путей монтирования; не сохранять импорт в `zpool.cache` |
| `backup`              | Имя конкретного пула                                                                      |

Таким образом, существующие настройки точек монтирования не заставят ZFS занять неожиданные каталоги твоей Raspberry Pi OS.

Это штатные возможности OpenZFS.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://openzfs.github.io\&sz=32)

OpenZFS documentation

+1



Если появится ошибка с требованием `-f`, не добавляй его автоматически. Это может означать, что ранее пул не был корректно экспортирован. Нужно сначала разобраться, почему.

### Посмотреть состояние пула

```
sudo zpool status -v backup
```

И список файловых систем:

```
sudo zfs list -r -o name,type,used,avail,mountpoint,mounted,canmount backup
```

Здесь мы узнаем реальные имена datasets, пути монтирования и возможности их подключения.

## 4. Монтирование файлов и каталогов

Когда пул успешно импортирован, можно подключить файловые системы:

```
sudo zfs mount -a
```

Эта команда монтирует доступные для автоматического монтирования ZFS datasets, включая datasets других импортированных пулов, если они есть.

Проверить результат:

```
sudo zfs mount
```

И, например:

```
ls -lah /mnt/zfs-inspect
```

Реальный путь к файлам будет зависеть от сохранённого свойства `mountpoint`. Если у корневого dataset оно `/backup`, то с указанным `altroot` ожидаемый путь:

```
/mnt/zfs-inspect/backup
```

Если datasets имеют `canmount=off`, `canmount=noauto`, `mountpoint=none` или `mountpoint=legacy`, их подключение потребует отдельного рассмотрения. Не нужно менять эти свойства ради первого чтения.

Если ZFS использует шифрование, могут потребоваться ключи.

## 5. Как правильно отключить ZFS-диск

Вот процедура, которую я рекомендую применять при каждом отключении.

Шаг 1. Завершить работу с файлами

Закрой программы, использующие диск, дождись окончания копирования и проверок. Закрой файловые менеджеры и SSH-сессии с рабочим каталогом внутри пула.

Шаг 2. Сбросить ожидающие записи

```
cd ~
sync
```

Шаг 3. Экспортировать ZFS-пул

```
sudo zpool export backup
```

Команда корректно размонтирует файловые системы и завершит использование пула. Для обычного режима записи экспорт обеспечивает штатное завершение операций ZFS.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://manpages.debian.org\&sz=32)

Debian Manpages



Шаг 4. Убедиться, что экспорт завершён

```
sudo zpool list
```

Твоего пула больше не должно быть в списке импортированных пулов.

Шаг 5. Отключить питание HDD

После успешного `zpool export` можно выключить соответствующий слот OWC штатной кнопкой питания.

Устройство может самостоятельно остановить вращение диска. Не вытаскивай HDD, пока он вращается.

Шаг 6. При необходимости выключить Raspberry Pi

```
sudo shutdown -h now
```

Дождись полного завершения работы Raspberry Pi.

Если `zpool export` возвращает `pool is busy` или другую ошибку, не отключай питание диска. Нужно найти процессы, которые ещё используют файловые системы пула. Не используй `zpool export -f` как обычное решение.

## 6. А если нужно будет записывать файлы?

После успешной первичной проверки можно экспортировать пул и повторно импортировать его в режиме чтения и записи.

Для того же условного имени `backup`:

```
sudo zpool export backup
```

```
sudo zpool import -N -R /mnt/zfs-inspect backup
```

Затем смонтировать нужные datasets.

Здесь уже отсутствует `readonly=on`, то есть ZFS сможет записывать данные на диск. Перед таким переходом важно убедиться, что SMART и состояние пула не указывают на серьёзные проблемы.

И ещё одна важная особенность ZFS: её собственная команда проверки целостности — `zpool scrub`. Она проверяет контрольные суммы занятых блоков, а не просто возможность прочитать каждый сектор, как `dd`. Однако scrub требует пул, импортированный для записи, и его лучше запускать только после первоначальной диагностики.

Документация: [OpenZFS — Troubleshooting](https://openzfs.github.io/openzfs-docs/Basic%20Concepts/Operations/Troubleshooting.html).
