Я бы подошёл к проверке твоего 22-ТБ HDD достаточно основательно. Особенно учитывая, что диск не включался примерно полтора года, а у тебя есть Raspberry Pi 5, на котором можно спокойно запустить диагностику на несколько суток.

Хорошая новость: само по себе хранение HDD без питания в течение полутора лет не означает, что он должен испортиться. Никаких специальных процедур «оживления» диска перед включением обычно не требуется.

Но я бы не ограничивался проверкой SMART. Я предлагаю провести диагностику в несколько этапов: от первого запуска до последовательного чтения всех 22 ТБ и анализа ошибок.

Главное условие: все начальные проверки будут без записи на диск, форматирования и изменения разделов. Мы будем исходить из того, что на нём могут находиться важные данные.

## 1. Что сделать до первого включения

Перед подачей питания рекомендую проверить следующее.

1. Температура и влажность. Если HDD хранился в обычной комнате, ничего ждать не нужно. Если он был в холодном подвале, гараже или на балконе, дайте ему прогреться до комнатной температуры, особенно чтобы исключить конденсат.
2. Внешний осмотр. Проверь отсутствие повреждений платы, SATA-разъёмов, следов коррозии или ударов.
3. Правильная установка в OWC. Убедись, что HDD до конца установлен в SATA-разъём док-станции. Переставлять его нужно только при отключённом питании соответствующего слота.
4. Питание. Используй штатный кабель и блок питания док-станции. Полноразмерный 3,5-дюймовый HDD должен получать питание от OWC, а не от USB-порта Raspberry Pi.
5. Устойчивость. Поставь док-станцию на ровную неподвижную поверхность с хорошей вентиляцией. Не перемещай диск, пока он вращается.

## 2. Первые команды на Raspberry Pi

Когда диск включён и раскрутился, подключись к Raspberry Pi через SSH.

Сначала выполни:

```
lsblk -o NAME,SIZE,MODEL,SERIAL,TRAN,FSTYPE,MOUNTPOINTS
```

Команда покажет все блочные устройства.

Например, твой HDD может оказаться `/dev/sda`, а его разделы — `/dev/sda1`, `/dev/sda2` и так далее.

Это только пример. Нельзя считать, что `/dev/sda` обязательно соответствует большому диску: на Raspberry Pi могут быть подключены NVMe, USB-накопители и другие устройства.

Затем проверь последние системные события:

```
sudo dmesg -T | tail -n 100
```

Нас будут интересовать сообщения:

- `I/O error`
- `medium error`
- `reset SuperSpeed USB device`
- `device offline`
- `uas` или `usb-storage`, особенно если рядом есть ошибки

Само по себе упоминание `uas` не свидетельствует о неисправности.

Также нужно удостовериться, что OWC видит все 22 ТБ, а не только часть диска. После определения устройства выполни:

```
sudo blockdev --getsize64 /dev/sdX
```

Здесь и далее `/dev/sdX` нужно заменить фактическим именем диска. Для номинального HDD 22 TB ожидается число порядка 22 триллионов байт.

Это особенно важно для проверки совместимости старой док-станции с очень большим накопителем.

## 3. Проверка SMART — состояние самого HDD

Это первый важный этап диагностики.

SMART позволяет прочитать внутреннюю статистику накопителя: наработку, температуру, ошибки чтения, переназначенные сектора и историю самодиагностики.

Установи пакет:

```
sudo apt update
sudo apt install smartmontools
```

Найди поддерживаемые устройства:

```
sudo smartctl --scan-open
```

Затем, подставив правильное имя диска, запусти:

```
sudo smartctl -x /dev/sdX
```

Если SMART недоступен через USB-док, попробуй:

```
sudo smartctl -x -d sat /dev/sdX
```

`-d sat` позволяет обращаться к SATA-диску через USB-SATA-контроллер, если тот поддерживает соответствующие команды. Но поддержка зависит от конкретного контроллера OWC.&#x20;

Важно проверить, что SMART показывает именно серийный номер твоего 22-ТБ HDD, а не другого накопителя в док-станции.

### На какие показатели смотреть

| Показатель SMART         | Что означает                                               |
| ------------------------ | ---------------------------------------------------------- |
| `Power_On_Hours`         | Сколько часов диск проработал                              |
| `Power_Cycle_Count`      | Количество циклов включения                                |
| `Reallocated_Sector_Ct`  | Переназначенные дефектные сектора                          |
| `Current_Pending_Sector` | Сектора с нестабильным чтением                             |
| `Offline_Uncorrectable`  | Неисправимые ошибки, обнаруженные при автономных проверках |
| `Reported_Uncorrect`     | Зарегистрированные неисправимые ошибки                     |
| `UDMA_CRC_Error_Count`   | Ошибки передачи по интерфейсу                              |
| `Temperature_Celsius`    | Температура накопителя                                     |

Названия и интерпретация некоторых атрибутов зависят от производителя.

Особенно интересны `Reallocated_Sector_Ct`, `Current_Pending_Sector` и `Offline_Uncorrectable`. В идеале они равны нулю, но даже нулевые показатели не доказывают, что диск полностью исправен. А статус `PASSED` не означает отсутствия всех проблем.

## 4. Запуск встроенной диагностики HDD

В SMART есть собственные тесты, которые выполняются контроллером диска.

Я рекомендую последовательно выполнить два.

### Сначала Short Self-Test

```
sudo smartctl -t short /dev/sdX
```

Это сравнительно быстрая проверка внутренних компонентов и части операций чтения. Обычно занимает несколько минут.

Проверка результата:

```
sudo smartctl -l selftest /dev/sdX
```

Нужный результат:

`Completed without error`

Если тест завершился ошибкой, дальнейшие действия зависят от характера ошибки и ценности данных.

### Затем Extended (Long) Self-Test

```
sudo smartctl -t long /dev/sdX
```

Это уже гораздо более серьёзная диагностика.

Контроллер HDD выполняет продолжительную внутреннюю проверку, включая чтение пользовательской области диска. У 22-ТБ модели она может занимать много часов, а иногда более суток.

После запуска `smartctl` обычно сообщает расчётное время завершения. Команда запускает тест внутри накопителя и завершается — SSH-сессию держать открытой не требуется.

Проверять состояние можно так:

```
sudo smartctl -c /dev/sdX
```

А после завершения:

```
sudo smartctl -l selftest /dev/sdX
```

У некоторых дисков доступен ещё и расширенный журнал:

```
sudo smartctl -l xselftest /dev/sdX
```

Последняя команда может не поддерживаться диском или USB-контроллером — это само по себе не признак неисправности.

Описание этих тестов есть в [документации smartctl](https://manpages.debian.org/bookworm/smartmontools/smartctl.8.en.html).

## 5. Полное чтение всех 22 ТБ

Я рекомендую выполнить и эту проверку, если SMART не обнаружит серьёзных неисправностей.

В отличие от встроенного Extended Self-Test, здесь Linux сам будет последовательно читать данные с самого начала диска до последнего доступного сектора через USB-подключение.

Таким образом, дополнительно проверяется тракт чтения через OWC и Raspberry Pi.

Команда:

```
sudo dd if=/dev/sdX of=/dev/null bs=16M iflag=direct status=progress
```

Это безопасное для содержимого диска чтение: `if=` указывает исходный HDD, а `of=/dev/null` означает, что прочитанные данные отбрасываются, а не записываются на диск.

Не меняй местами `if` и `of`.

Опция `iflag=direct` позволяет читать, минуя обычный файловый кеш. `status=progress` показывает продвижение.&#x20;

### Сколько времени займёт проверка?

Расчёт для последовательного чтения 22 TB без остановок

| Средняя скорость | Время     |
| ---------------- | --------- |
| 100 MB/s         | 61,1 часа |
| 150 MB/s         | 40,7 часа |
| 200 MB/s         | 30,6 часа |
| 250 MB/s         | 24,4 часа |

Это математические оценки, не измеренные скорости твоего HDD. Реальная скорость будет меняться по поверхности диска.

Для длительной проверки через SSH советую использовать `tmux`, чтобы обрыв соединения не прервал чтение:

```
sudo apt install tmux
tmux new -s hddcheck
```

В открывшейся сессии запусти `dd`. Отключиться от сессии можно сочетанием `Ctrl+B`, затем `D`.

Вернуться:

```
tmux attach -t hddcheck
```

После полного чтения повтори SMART:

```
sudo smartctl -x /dev/sdX
```

Мы сможем сравнить значения до и после проверки.

## 6. Мониторинг температуры и ошибок

Для многосуточной диагностики важно не только запустить тесты, но и контролировать условия работы.

Температуру можно проверять командой:

```
sudo smartctl -A /dev/sdX
```

В качестве консервативного практического ориентира я бы стремился удерживать HDD примерно в пределах 30–45 °C. Если температура приближается к 50 °C и продолжает расти, стоит улучшить охлаждение. Точный допустимый предел зависит от модели диска.

Также проверяй ошибки USB и I/O:

```
sudo dmesg -T | tail -n 100
```

Если появляются многочисленные `USB reset`, `I/O error` или диск пропадает из системы, это не обязательно означает неисправность самого HDD. Возможны проблемы с кабелем, контроллером, питанием или USB-соединением.

## 7. Проверка файловой системы

Это отдельная задача. SMART и последовательное чтение проверяют доступность и физическое состояние накопителя, но не гарантируют целостность каталогов, файлов и метаданных файловой системы.

После выполнения предыдущих этапов я бы проверил ещё и файловую систему, но команду выбрал бы только после определения её типа.

Например, для ext4, XFS, Btrfs и NTFS используются разные инструменты. На первом этапе выбираем диагностику без исправлений.

Пока не используй `fsck -y`, `badblocks -w`, `mkfs` или другие команды, способные изменять содержимое диска.

## Какой результат я считаю достаточным

SMART — без критичных проблем и ухудшающихся показателей

Short Self-Test — Completed without error

Extended Self-Test — Completed without error

Полное чтение 22 ТБ — без ошибок I/O и USB-отключений

Файловая система — проверена на целостность

Даже успешное прохождение всех тестов не гарантирует, что диск не выйдет из строя завтра. Поэтому важные файлы должны иметь независимую резервную копию.

И существенная оговорка: если на HDD хранятся уникальные данные, которых больше нигде нет, сначала нужно оценить SMART и по возможности скопировать важное. Многосуточные стрессовые проверки потенциально опасны для уже деградировавшего накопителя.

Можешь включать диск, если он находился в обычных комнатных условиях, надёжно установлен и подключён к штатному питанию OWC.

После включения выполни эти три команды:

```
lsblk -o NAME,SIZE,MODEL,SERIAL,TRAN,FSTYPE,MOUNTPOINTS
```

```
lsusb
```

Пришли мне вывод всех трёх команд. По ним я определю, какой именно HDD видит Raspberry Pi, как он подключён через OWC, полностью ли определяется его ёмкость и нет ли ошибок уже при первом запуске.

После этого сможем перейти к SMART и организовать полноценное многосуточное тестирование без риска случайно отформатировать или перезаписать данные.
